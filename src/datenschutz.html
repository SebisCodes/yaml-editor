A6. Ihre Dokumente bleiben in Ihrem Browser

Der YAML-Editor ist ein Programm, das vollständig in Ihrem Browser läuft. Was Sie schreiben, öffnen, einfügen oder exportieren, wird auf Ihrem Gerät verarbeitet und nicht an uns übermittelt. Wir haben keinen Zugriff darauf. (Zum Dokument, das eine andere Website per Formular sendet, siehe A12.)

Damit Ihre Arbeit beim Neuladen nicht verloren geht, speichert der Editor im lokalen Speicher Ihres Browsers (localStorage, je nach Editor auch IndexedDB; Einzelheiten in Teil B) und, für Zugangszeichen, im Sitzungsspeicher des Tabs (sessionStorage):

Eintrag Inhalt Wie lange
yamleditor.files Liste Ihrer Dokumente ("Meine Dokumente"): Name, Erstellungs- und Änderungsdatum, Grösse und, falls eingerichtet, das Speicherziel des Dokuments mit Adresse (A8) bis Sie das Dokument löschen
yamleditor.file.<Kennung> der Inhalt (Code) eines Dokuments bis Sie das Dokument löschen
yamleditor.v1 Einstellungen der Oberfläche und das zuletzt geöffnete Dokument (Teil B) bis Sie die Websitedaten löschen

Diese Einträge verlassen Ihr Gerät nicht. Sie sind für die Funktion nötig, die Sie nutzen (Ihre Dokumente aufbewahren, Ihre Einstellungen behalten) und enthalten keine Kennung, mit der Sie wiedererkannt werden könnten. Sie können sie jederzeit entfernen: einzelne Dokumente in "Meine Dokumente", alles zusammen über die Einstellungen Ihres Browsers ("Websitedaten löschen"). Ihre Dokumente sind dann unwiderruflich weg. Sie können die Speicherung für yaml.giit.ch in Ihrem Browser sperren; der Editor kann Ihre Arbeit dann nicht dauerhaft aufbewahren. In einem privaten Fenster kann der Browser Daten während der privaten Sitzung speichern und beim Beenden dieser Sitzung löschen.

Der Browser kann gespeicherte Daten selbst löschen, etwa bei Speicherknappheit oder in privaten Fenstern. Bewahren Sie wichtige Dokumente deshalb zusätzlich als Datei auf.

In der reinen Ansicht (Adresse mit ?viewer=1) speichert der Editor nichts in Ihrem Browser und zeigt Ihre gespeicherten Dokumente nicht an.

A7. Zwischen Ihren Browser-Tabs und in der Zwischenablage

Ist der Editor in mehreren Tabs offen, tauschen die Tabs über einen Kanal Ihres Browsers (BroadcastChannel) kurze Meldungen aus, etwa welcher Tab zuletzt benutzt wurde, und übergeben ein Dokument aus einem KI-Link an diesen Tab. Diese Meldungen bleiben in Ihrem Browser.

"Prompt kopieren" und andere Kopierfunktionen legen Text in Ihrer Zwischenablage ab. Dabei wird nichts übermittelt.

Wählen Sie "In einem anderen Editor öffnen" (nicht in jedem Editor vorhanden), wandelt der Editor das Dokument in Ihrem Browser um und öffnet den anderen giit Editor in einem neuen Tab. Das Dokument steht dabei im Link nach dem Zeichen "#" und erreicht deshalb keinen Server (A10); der andere Editor legt es in seinem eigenen Speicher in Ihrem Browser ab (A6).

A8. Speichern auf einem eigenen Server (Webhook, freiwillig)

Tragen Sie unter "Auf Server speichern" eine Adresse ein oder öffnen Sie einen Link mit ?webhook= und erlauben das Speichern, sendet der Editor beim Speichern - auf Wunsch auch automatisch kurz nach jeder Änderung - das Dokument direkt aus Ihrem Browser an diese Adresse: Editor, Kennung, Name, Inhalt, Änderungszeit und, je nach Editor, die Bilder und Dateien des Dokuments (Teil B). Haben Sie ein Zugangszeichen eingetragen, wird es mitgesendet. Die Anfrage geht nicht über unseren Server. Der Server unter der Adresse erhält dabei auch Ihre IP-Adresse und die üblichen Angaben Ihres Browsers, als Herkunft nur die Adresse unserer Website (ohne Pfad) und keine Cookies.

Eine einbettende Website kann für das von ihr übergebene Dokument ein Speicherziel, ein Zugangszeichen und automatisches Speichern vorgeben. Dafür zeigt der Editor keinen eigenen Bestätigungsdialog. Das Speicherziel kann auch auf einem anderen Server liegen (A12).

Wir erhalten diese Daten nicht. Verantwortlich für ihre Bearbeitung ist der Betreiber des Servers, an den Sie sie senden. Eine Adresse, die Sie selbst eintragen, bleibt in Ihrem Browser gespeichert, das Zugangszeichen nur, bis Sie den Tab schliessen (A6); Angaben aus einem Link oder von einer einbettenden Website werden nur für die Dauer der Sitzung im Arbeitsspeicher gehalten. Zu Links mit ?webhook= siehe auch A4 (Parameter in der Adresse).

A9. Dateien aus einer Adresse und Inhalte, auf die Ihr Dokument verweist

Datei aus einem Link. Öffnen Sie einen Link mit ?src=<Adresse>, lädt Ihr Browser die Datei von dieser Adresse, ohne Cookies mitzusenden. Der Server unter dieser Adresse erhält dabei Ihre IP-Adresse und die üblichen Angaben Ihres Browsers; für ihn ist sein Betreiber verantwortlich.

Verweise im Dokument. Je nach Editor kann Ihr Dokument auf Bilder oder andere Inhalte auf fremden Websites verweisen (z. B. eine https-Adresse). Damit die Vorschau sie zeigen kann, lädt Ihr Browser sie von dort; die betreffende Website erhält dabei Ihre IP-Adresse, die üblichen Angaben Ihres Browsers und als Herkunft die Adresse unserer Website (ohne Pfad). Ob das geschieht, hängt vom Inhalt Ihres Dokuments ab, nicht von uns. Welche Editoren das betrifft, steht in Teil B. Für die Bearbeitung durch diese Websites sind ihre Betreiber verantwortlich.

A10. KI-Assistent (freiwillig)

"Prompt kopieren" legt Anweisungen und Ihr aktuelles Dokument in Ihrer Zwischenablage ab. Der Editor sendet dabei nichts. Der Prompt enthält auch den Dokumentnamen und, beim gewöhnlichen Prompt ohne KI-Konfiguration der einbettenden Website, die Namen von bis zu 40 weiteren gespeicherten Dokumenten. Je nach Editor kommen Namen zugehöriger Bilder und Dateien, ausgewählter Text, Prüfmeldungen und weitere Angaben zum Dokument hinzu. Prüfen Sie den kopierten Text, bevor Sie ihn weitergeben. Fügen Sie den Text bei einem KI-Dienst Ihrer Wahl ein, bearbeitet dieser ihn nach seinen eigenen Bedingungen und seiner eigenen Datenschutzerklärung; dafür ist der Anbieter des KI-Dienstes verantwortlich, nicht wir. Fügen Sie keine Inhalte ein, die Sie diesem Anbieter nicht anvertrauen möchten.

Die KI antwortet mit Links, die das Dokument nach dem Zeichen "#" enthalten. Diesen Teil eines Links senden Browser nie an einen Server; das Dokument gelangt also nicht zu uns, wenn Sie einen solchen Link öffnen. Liefert die KI ein Dokument in mehreren Links, bewahrt der Editor die Teile auf, bis alle da sind (A6).

A11. Browser-Agenten (WebMCP, freiwillig)

Bietet Ihr Browser einen KI-Agenten an, der Websites über die Schnittstelle WebMCP bedienen kann, stellt der Editor ihm Werkzeuge zur Verfügung: Dokument lesen, ändern, Probleme anzeigen, Dokumente auflisten, öffnen und neu anlegen. Ein solcher Agent kann damit alle Dokumente in "Meine Dokumente" lesen und ändern, nicht nur das offene. Ob und wie der Agent diese Inhalte an seinen Anbieter übermittelt, bestimmen Ihr Browser und der Anbieter des Agenten nach ihren eigenen Bedingungen; sie sind dafür verantwortlich. Der Editor selbst sendet dabei nichts an einen Server.

A12. In andere Websites eingebettet oder von ihnen geöffnet

Andere Websites können den Editor in einem Rahmen oder einem eigenen Fenster anzeigen und mit ihm Dokumente austauschen. Die Seiten des Editors werden auch dann von unserem Server geladen (A4, A5). Zurück an die einbettende Website gehen nur das Dokument, das sie dem Editor übergeben hat, und Änderungen daran (Inhalt, Name, Bilder und Dateien, bei einigen Editoren auch ein PDF), nie Ihre übrigen Dokumente. Das übergebene Dokument und seine Bilder hält der Editor nur im Arbeitsspeicher: Sie werden nicht in Ihrem Browser gespeichert und sind weg, wenn der Editor geschlossen wird. Ein neues Dokument, das eine KI über die einbettende Website liefert, bleibt dagegen in Ihrem Browser (A6).

Eine einbettende Website kann für das von ihr übergebene Dokument ein Speicherziel, ein Zugangszeichen und automatisches Speichern vorgeben. Dafür zeigt der Editor keinen eigenen Bestätigungsdialog. Das Speicherziel kann auch auf einem anderen Server liegen (A8).

Eine einbettende Website kann dem Editor zudem eine Adresse und einen Schlüssel für KI-Ergebnisse übergeben. Der Schlüssel wird nur im Arbeitsspeicher gehalten, bis die Sitzung endet oder die Website, die den Editor geöffnet hat, geschlossen wird, und steht im Klartext im kopierten Prompt; mit dem Prompt gelangt er an den KI-Dienst, den Sie wählen. Die KI sendet ihr Ergebnis an den Server der einbettenden Website.

Für alle Daten, die die einbettende Website erhält, ist ihr Betreiber verantwortlich; es gilt seine Datenschutzerklärung. Wir erhalten diese Daten nicht.

Dokument per Formular. Eine andere Website kann ein Dokument im Editor öffnen, indem Ihr Browser es als Formular an die Adresse post.php des Editors sendet. Unser Server erhält dabei das Dokument, gegebenenfalls seinen Namen und die gewünschte Sprache der Seite sowie die üblichen Angaben jeder Anfrage (A4). Er prüft Art und Grösse (höchstens 20 MB Text) und gibt den Inhalt unverändert in seiner Antwort an Ihren Browser zurück. Er schreibt das Dokument in keine Datei und keine Datenbank und protokolliert es nicht; nach der Antwort ist es auf dem Server nicht mehr vorhanden. Die Zugriffsprotokolle von lima-city enthalten wie bei jedem Aufruf die Adresse mit ihren Parametern (etwa ?viewer=1, A4), nach dessen Angaben aber nicht den Inhalt des Formulars. In der Nutzungsstatistik wird der Aufruf nicht gezählt (A4). Im Browser hält der Editor das Dokument nur im Arbeitsspeicher: Es wird nicht im Speicher Ihres Browsers abgelegt und ist weg, wenn der Editor geschlossen wird. Welches Dokument gesendet wird, bestimmt die sendende Website; für ihre eigene Bearbeitung gilt ihre Datenschutzerklärung.
