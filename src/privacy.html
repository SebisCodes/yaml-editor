A2. Summary

  • The editors run entirely in your browser. Your documents are not sent to us; they stay on your device unless you or an embedding website use a feature to share them (A8 to A12).
  • The only exception: if another website opens a document in the editor with a form, it passes once through our server, which hands it straight on to your browser and does not store it (A12).
  • There are no accounts, no tracking across websites, no advertising and no profiling. We count page views on our own server without cookies, using a daily changing pseudonymous identifier (A4). Fonts, scripts and programs of the editors are loaded only from our own website.
  • When you open the website, our hosting provider lima-city (TrafficPlex GmbH, Germany) records technical access data, including your full IP address and the address requested; these logs are kept for up to 90 days (A4).
  • lima-city sets technical cookies without any personal identifier to protect against automated access (A5).
  • Data leaves your device when you use a feature for it or an embedding website configures it for the document it supplies: saving to a server (webhook), loading a file from an address, pictures or other content your document refers to, an AI service or browser agent of your choice, or another website that has embedded the editor (A8 to A12). Saving to the destination server goes directly from your browser to it, not through us.
  • Under the Swiss Federal Act on Data Protection you have, in particular, the right of access (A15).

A4. Visiting the website: hosting by lima-city, server logs and usage statistics

The website is run by lima-city, a service of TrafficPlex GmbH, Konsul-Smidt-Str. 90, 28217 Bremen, Germany. lima-city processes the data as our processor.

To deliver a page or file, the web server processes your device's IP address and the information your browser sends with each request. According to lima-city, it logs:

  • the full IP address and the date and time;
  • the domain and address requested, including the parameters in the address (the part after "?", see below);
  • HTTP method, protocol version, response status, amount of data transferred and response times;
  • browser and connection characteristics, in particular the browser identifier (user agent), language settings and technical characteristics of the encrypted connection;
  • technical security information, such as the reason for a block;
  • an access ID that allows a single request and related error messages to be found.

The IP address in the access logs is neither shortened nor anonymized.

Purpose: delivering the website, investigating faults, and detecting and preventing misuse, bots and attacks. We do not analyze the logs to recognize visitors and do not combine them with other data.

Retention (as stated by lima-city):

Log Retention
Access logs up to 90 days
Error logs and access IDs up to 7 days
Short-term analyses to block repeated attacks (e.g. counters per IP address) up to 1 day

Parameters in the address. If you open a link that contains information after a "?", such as ?src= (load a file from an address), ?webhook= (save target) or ?lang= (language), this information reaches our server with the request and ends up in lima-city's access logs, even though the editor removes it from the address bar immediately afterwards. The editor does not use an access token in such a link; if a link contains one anyway, it is logged as well. Information after a "#", by contrast, never reaches any server (A10). A document that another website sends with a form (A12) is not part of the address.

Location and disclosure abroad: The website and its logs are run in the Telehouse data center in Frankfurt am Main, Germany (lima-city web hosting package "Mini"). Backups of the website files are kept by Hetzner in Helsinki, Finland; the website files contain no personal data of visitors. According to the decision of the Federal Council (Annex 1 DPO), Germany and Finland provide an adequate level of data protection.

lima-city's current information is at https://www.lima-city.de/hilfe/welche-daten-speichert-lima-city-von-webseitenbesuchern.

Usage statistics without cookies. To see which pages and editors are used, we count every page view on our own server. Nothing is stored on or read from your device for this: no cookie, no script, no tracking pixel. Only information your browser sends with the request anyway is used, and only in a coarsened form:

  • date and hour (without minutes), the website and page requested (without the part after "?" or "#");
  • the country, derived from the IP address with a table on our server (IP Geolocation by DB-IP, https://db-ip.com); no region, no city;
  • the preferred language, the browser family with its major version (e.g. "Firefox 145"), the operating system without version and the device class (desktop, mobile, tablet);
  • which website you came from, only its name (e.g. google.com), never the full address;
  • a daily changing identifier that groups requests from the same browser within one day per website: a hash of IP address, browser identifier and website, made with a random key created anew for each day. The statistics do not store IP addresses in plain text. While the daily key exists, the identifiers are pseudonymized. The daily key becomes due for deletion the next day and is deleted during the next successfully completed cleanup.

Only requests for pages are counted; a document sent with a form (A12) is not counted. Views by bots are only recorded as a number per day. Individual views and daily bot counts become due for deletion once six full calendar months have passed after the month of the view (so after seven months at the latest). They are deleted after the next successfully completed cleanup; only monthly totals of the individual views remain (views and visitors per website).

Cleanup is triggered by the first counted page view of a day when the new daily key is created. Without such a request, this mechanism does not delete the data. Technical errors may delay deletion. The periods stated are therefore not maximum retention periods independent of page views and successful cleanup. The data is kept in a separate database at lima-city in Germany (as above), is not disclosed and is not combined with any other data; only the controller can see it, after logging in. Objection: If your browser sends "Global Privacy Control" or "Do Not Track", your view is not counted. Legal basis: our overriding interest in improving the website (Art. 31(1) FADP).

We set a single cookie ourselves, and only when you choose a language in the language menu:

Cookie Content and purpose Expiry
lang code of the chosen language (e.g. "de"); remembers your choice for giit.ch and its subdomains. Until you choose a language, your browser's language applies. one year after the choice

The editors keep your work and settings in your browser's local storage (A6). Our hosting provider also sets the following cookies for its bot protection:

Cookie Content and purpose Expiry
_lcp value "a"; marks the request for a page (set by the server, not readable by scripts) 20 March 2034
_lcp2 value "a"; marks a follow-up request for a file, such as a picture (set by the server, not readable by scripts) 20 March 2034

The value of these cookies is the same for all visitors and contains no personal identifier. They serve only to distinguish automated requests from ordinary browser visits and so protect the website against attacks. They apply only to yaml.giit.ch.

You can refuse or delete cookies in your browser settings. Without the cookie lang, your browser's language or the language of the requested address applies. Because the bot-protection cookies serve the security of the website, there is no guarantee that the bot protection will let requests through without them.

A6. Your documents stay in your browser

The YAML Editor is a program that runs entirely in your browser. What you write, open, paste or export is processed on your device and not sent to us. We have no access to it. (For a document that another website sends with a form, see A12.)

So that your work is not lost when you reload the page, the editor stores in your browser's local storage (localStorage, and IndexedDB for some editors; details in Part B) and, for access tokens, in the tab's session storage (sessionStorage):

Entry Content How long
yamleditor.files list of your documents ("My documents"): name, creation and change date, size and, if set up, the document's save target with address (A8) until you delete the document
yamleditor.file.<id> the content (code) of a document until you delete the document
yamleditor.v1 interface settings and the document opened last (Part B) until you clear site data
yamleditor.hook general save target (webhook): address and whether saving is automatic (A8) until you remove it or clear site data
yamleditor.tokens (sessionStorage) access tokens of the save targets you enter (A8) until you close the tab
yamleditor.theme chosen color theme (light, dark, automatic) until you clear site data
yamleditor.wrap whether long lines in the code are shown wrapped until you clear site data
yamleditor.parts.<…> parts of a document that an AI delivers in several links (A10) until all parts have arrived; incomplete parts remain until you clear site data

These entries do not leave your device. They are needed for the function you use (keeping your documents and settings) and contain no identifier that could recognize you. You can remove them at any time: single documents in "My documents", everything at once in your browser settings ("Clear site data"). Your documents are then gone for good. You can block storage for yaml.giit.ch in your browser; the editor then cannot retain your work persistently. In a private window, the browser may store data during the private session and delete it when that session ends.

The browser may delete stored data on its own, for example when storage runs low or in private windows. Keep important documents as a file as well.

In the read-only view (an address with ?viewer=1) the editor stores nothing in your browser and does not show your stored documents.

A7. Between your browser tabs and in the clipboard

If the editor is open in several tabs, the tabs exchange short messages through a channel of your browser (BroadcastChannel), for example which tab was used last, and hand a document from an AI link to that tab. These messages stay in your browser.

"Copy prompt" and other copy functions put text on your clipboard. Nothing is sent.

If you choose "Open in another editor" (not in every editor), the editor converts the document in your browser and opens the other giit editor in a new tab. The document is carried in the link after the "#" sign and therefore reaches no server (A10); the other editor keeps it in its own storage in your browser (A6).

A8. Saving to your own server (webhook, optional)

If you enter an address under "Save to server", or open a link with ?webhook= and allow saving, the editor sends the document directly from your browser to that address when you save - if you wish, also automatically shortly after each change: editor, ID, name, content, time of change and, depending on the editor, the document's pictures and files (Part B). If you entered an access token, it is sent too. The request does not pass through our server. The server at that address also receives your IP address and the usual browser information, as origin only the address of our website (without path), and no cookies.

An embedding website can specify a save destination, access token and automatic saving for the document it supplies. The editor does not show its own confirmation dialog for this. The destination may be on another server (A12).

We do not receive this data. The operator of the server you send it to is responsible for its processing. An address you enter yourself stays stored in your browser, its access token only until you close the tab (A6); values from a link or from an embedding website are kept in memory for the session only. For links with ?webhook= see also A4 (parameters in the address).

A9. Files from an address and content your document refers to

File from a link. If you open a link with ?src=<address>, your browser loads the file from that address without sending cookies. The server at that address receives your IP address and the usual browser information; its operator is responsible for it.

References in the document. Depending on the editor, your document may refer to pictures or other content on other websites (e.g. an https address). So that the preview can show them, your browser loads them from there; that website receives your IP address, the usual browser information and, as origin, the address of our website (without path). Whether this happens depends on the content of your document, not on us. Part B lists the editors concerned. The operators of those websites are responsible for their processing.

A10. AI assistant (optional)

"Copy prompt" puts instructions and your current document on your clipboard. The editor sends nothing. The prompt also contains the document name and, for the ordinary prompt without an embedding website's AI configuration, the names of up to 40 other saved documents. Depending on the editor, it also includes names of associated pictures and files, selected text, diagnostics and other document details. Review the copied text before sharing it. If you paste the text into an AI service of your choice, that service processes it under its own terms and privacy policy; the provider of the AI service is responsible for that, not we. Do not paste content you do not want to entrust to that provider.

The AI answers with links that carry the document after the "#" sign. Browsers never send this part of a link to a server, so the document does not reach us when you open such a link. If the AI delivers a document in several links, the editor keeps the parts until all of them are there (A6).

A11. Browser agents (WebMCP, optional)

If your browser offers an AI agent that can operate websites through the WebMCP interface, the editor provides it with tools: read and change the document, show problems, list, open and create documents. Such an agent can therefore read and change all documents in "My documents", not only the open one. Whether and how the agent sends this content to its provider is decided by your browser and the agent's provider under their own terms; they are responsible for it. The editor itself sends nothing to any server.

A12. Embedded in or opened by other websites

Other websites can show the editor in a frame or a window of their own and exchange documents with it. The editor's pages are still loaded from our server (A4, A5). Only the document the embedding website handed to the editor, and changes to it (content, name, pictures and files, for some editors also a PDF), go back to that website - never your other documents. The editor keeps the document handed over and its pictures in memory only: they are not stored in your browser and are gone when the editor closes. A new document an AI delivers through the embedding website, by contrast, stays in your browser (A6).

An embedding website can specify a save destination, access token and automatic saving for the document it supplies. The editor does not show its own confirmation dialog for this. The destination may be on another server (A8).

An embedding website can also give the editor an address and a key for AI results. The key is kept in memory only until the session ends or the website that opened the editor is closed, and appears in plain text in the copied prompt; with the prompt it reaches the AI service you choose. The AI sends its result to the embedding website's server.

The operator of the embedding website is responsible for all data that website receives; its privacy policy applies. We do not receive this data.

Document sent with a form. Another website can open a document in the editor by having your browser send it as a form to the editor's address post.php. Our server then receives the document, its name and the requested page language if given, and the usual information of every request (A4). It checks type and size (at most 20 MB of text) and returns the content unchanged in its answer to your browser. It writes the document to no file and no database and does not log it; once the answer is sent, it no longer exists on the server. lima-city's access logs contain, as for every request, the address with its parameters (such as ?viewer=1, A4) but, according to lima-city, not the content of the form. The request is not counted in the usage statistics (A4). In the browser the editor keeps the document in memory only: it is not written to your browser's storage and is gone when the editor closes. Which document is sent is decided by the sending website; its own privacy policy applies to its own processing.

A14. Disclosure, data security, no automated decisions

We do not sell personal data and do not pass it on to third parties. The only recipients are the processors named (lima-city with its sub-processors for hosting, Microsoft for email) and authorities where we are legally obliged.

The website is delivered over encrypted connections (HTTPS) only. A browser security policy (Content Security Policy) prevents the editors from loading scripts from other servers.

There are no decisions based solely on automated processing and no profiling.

Particulars of this editor

YAML Editor (yaml.giit.ch)
